# 知识库采集说明

本文档说明监管知识库的数据来源、采集方法、质量控制与更新流程，
对应论文"数据集构建"一节。

## 1. 数据规模（当前版本）

| 指标 | 数值 |
|---|---|
| 文档总数 | **315 篇** |
| ├ 监管法规（regulation） | 84 篇 |
| ├ 行政处罚决定书（penalty） | 212 篇 |
| └ 重大案件处罚通报（announcement） | 19 篇 |
| 条款级切分块数 | **7,840 块**（含条款号 7,525 块，占 96%） |
| 语料总字数 | 约 127 万字 |
| 维度分布 | D1 信息披露 108 / D2 治理 30 / D3 内控合规 124 / D4 声誉 53 |
| 时间跨度 | 1993 年（股票发行与交易管理暂行条例）至 2026 年最新处罚 |

归档目录 `data/knowledge_base_archive/` 保存同一法规的旧版本 34 篇（法规沿革
对照，不进入检索索引）。

## 2. 数据来源

### 2.1 国家法律法规数据库（flk.npc.gov.cn）

`scripts/collect_regulations.py` 采集法律、行政法规层面的骨干法规 40 篇
（证券法、公司法、会计法、审计法、期货交易管理条例等）：

1. `POST /law-search/search/list` 按标题关键词检索（`searchRange=1`），
   仅保留"有效"（`sxx=3`）条目，白名单（金融监管核心词）+ 黑名单
   （无关行业词）双重过滤；
2. `GET /law-search/search/flfgDetails` 取元数据与 OSS 文件路径（优先 Word）；
3. `GET /law-search/amazonFile/ofdGenerateLink` 换取签名下载 URL
   （签名 Host 为内网域名，按 SigV4 规则保持 Host 头、TCP 连接指向外网 IP
   即可下载，纯 stdlib socket 实现）；
4. docx 用 zip+xml 解析条文；PDF 用 pdfplumber 双栏重排（公报版式）。

### 2.2 中国证监会官网（csrc.gov.cn）

`scripts/collect_csrc.py` 采集部门规章与规范性文件（信息披露管理办法、
上市公司治理准则、独立董事管理办法、股东大会规则、章程指引等）：

1. `POST /guestweb4/s` 全站搜索（开普云站群接口）；
2. 结果解析兼容两种链接形态（`title` 属性 / 锚文本），按栏目属性
   （`data="规章"` 等）过滤，排除征求意见、批复、新闻类噪音；
3. 正文提取支持 5 种页面容器（content-body / detail-news / detail_content /
   TRS_Editor / zoom）；令号、公告类页面正文在 PDF/DOCX 附件中时自动回退
   附件解析（按 magic number 识别 PDF/ZIP）。

### 2.3 行政处罚决定书专项

`scripts/collect_penalties.py` 以 `pageNum` 分页遍历证监会行政处罚栏目
（c101928），采集正式处罚决定书：

- **可读标题生成**：决定书标题千篇一律，从 meta description / 正文提取
  "〔年份〕编号 + 当事人"生成可区分标题；
- **维度弱标注**：依据违法事实关键词规则判定维度
  （D1 信披违规 / D2 治理失范 / D3 内控财务 / D4 市场行为），
  论文中作为弱监督标签使用并说明局限。

### 2.4 重大案件通报

csrc 脚本同时采集"证监会对 X 案作出行政处罚"类通报（獐子岛、北京文化等），
类型标记为 `announcement`，补充近年标志性案件语料。

## 3. 知识库文件格式

每篇文档一个 txt 文件，头部为 6 行元数据，`---` 后为正文：

```
@DOC_ID: DOC226
@TITLE: 【第226号令】《上市公司信息披露管理办法》
@TYPE: regulation            # regulation | penalty | announcement
@SOURCE: 中国证监会
@DATE: 2025-03-28
@DIMENSION: D1               # D1-D4 维度弱标签
---
第一条 为了规范……
```

`data/knowledge_base/manifest.json` 为统一清单（由
`scripts/dedupe_and_manifest.py` 从文件头重建，含去重、统计）。

## 4. 质量控制

- **有效性过滤**：仅收录现行有效法规（flk `sxx=3`），失效版本自动排除；
- **多版本去重**：同一法规的不同修订版保留内容最长（最新全文）一版，
  旧版移入 `knowledge_base_archive/`；
- **正文完整性校验**：正文 < 200 字（法规）/ < 300 字（处罚）视为失败并
  记录日志；
- **条款切分验证**：96% 的块成功解析出"第X条"条款号，支撑引用级溯源。

## 5. 检索评测集

`scripts/build_query_set.py` 基于扩充后知识库重建 40 条评测查询
（每维度 10 条），输出两个文件：

- `data/annotation/retrieval_queries.csv`：弱监督预标版
  （`label_source=weak_auto`，多关键词组命中规则），可直接跑通实验 02；
- `data/annotation/retrieval_queries_for_annotation.csv`：人工标注工作表
  （隐藏答案 + 候选池），两位标注者按 `docs/标注规范.md` 独立复核，
  计算 Cohen's Kappa ≥ 0.6 后仲裁定稿，替换为正式 gold 集。

> **注意**：弱标注由关键词规则生成，天然偏袒稀疏检索，正式论文实验
> 必须使用人工复核后的 gold 集，并在论文中报告标注一致性。

## 6. 增量更新

三个采集脚本均支持增量模式：启动时读取既有 manifest 的 URL 集合自动跳过
已采集文档。追加采集后直接运行：

```bash
python scripts/collect_regulations.py     # flk 法规
python scripts/collect_csrc.py            # 证监会规章/通报
python scripts/collect_penalties.py --pages 30
python scripts/dedupe_and_manifest.py     # 去重 + 重建清单
python scripts/build_query_set.py         # 重建查询集（如有新维度文档）
```

## 7. 仓库内置语料与完整语料

受仓库体积限制，GitHub 仓库内置：全部 212 篇处罚决定书、19 篇案件通报、
24 篇骨干法规（四维度核心监管规则全文）。其余法规全文与旧版归档由采集
脚本一键重建（增量幂等，约 30 分钟），清单以 `manifest.json` 为准。
